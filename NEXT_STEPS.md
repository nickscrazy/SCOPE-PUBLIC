# SCOPE — operational and commercial next steps

The local product is a functional prototype. Nothing has been publicly deployed or purchased.

1. **Review security and privacy before accepting real customer data.** Assign a legal controller, publish contact/retention/rights procedures, review access and session handling, implement full account erasure and test backup deletion. Add verified email ownership, secure recovery, password changes and session revocation. Financial bands and profile information are self-declared.
2. **Qualify sources and matching with real businesses.** Review original notice documents and lot context, source explicit mandatory requirements, add reliable amendment/cancellation handling and expiry rules. Expand the bounded Malta TED feed only after checking fair use. Arrange authorised ePPS access; no scraping workaround. Validate value from user research; no outcome metric is claimed.
3. **Create an accountable funding publishing workflow.** Add an admin UI with roles, recorded reviewer identity, verification evidence and approval history; independently verify all scheme rules, aid types and dates. Respect 403 responses. Recheck the two FONDI references. Micro Invest remains unverified. Current CLI import is for a trusted database operator only.
4. **Operate a staging instance once authorised.** Use TLS, a persistent private volume, encrypted tested backups, a single writer deployment, monitored health and source failures, request/error telemetry without personal data, rollback and a retention/pruning job. Exercise the supplied container configuration in the target environment; it was not built here. Perform load and disaster-recovery tests. Choose managed Postgres if moving to multiple replicas.
5. **Payments and communications only after connection and approval.** Solo €19 and Team €59 are hypotheses. Team workspaces are not implemented. Connect a billing provider, verify webhook entitlements and cancellation/tax flows before offering paid access. Add SMTP/provider credentials, consent and delivery testing before any verification, trial or transactional messages. No fake checkout or request-paid-access email currently exists.
6. **Finish commercial readiness.** Clear the name/domain/trademark, agree liability and support terms, test willingness to pay against public/free assistance (including SEM), and commission independent accessibility and legal reviews. Test other browsers, assistive technologies and real touch devices; Chromium and axe checks do not establish full accessibility compliance.

No model API is needed. Optional model summaries would need grounded citations, hostile-input handling, evaluation, cost controls and human uncertainty language before use.
