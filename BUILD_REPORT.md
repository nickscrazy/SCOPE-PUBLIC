The official live TED adapter was exercised successfully. It is **not CONNECTED_BETA or PRODUCTION_READY**: independent security/privacy qualification, operated hosting/monitoring, comprehensive source assessment and commercial infrastructure are not complete.

Built locally in `/workspace/scope` on 25 October 2026. No deployment, payment, customer communication, application, paid API or ePPS scraping was performed. There are no shared passwords or fabricated customers, partnerships, reviews or outcome metrics.

## Run, review and deployment

See [README.md](README.md) for clean setup, production commands, schema/entitlement semantics, source limits, operator import, backup/rollback guidance and deployment preparation. Start with `npm ci`, migrate/seed, then `npm run dev`. Register your own account; no shared password is provided. The main local database includes live TED records, while a clean checkout can seed funding references and run its own permitted TED sync.

Production requires an authorised HTTPS origin, private persistent storage and a single writer instance. Container configuration is supplied but not executed. No public deployment is claimed. The brand/domain/trademark and controller identity remain unqualified.

## Operating costs and commercial limits

No paid API/model usage is necessary. TED access and this curation flow use public sources. Rough planning allowances, **not verified provider quotes**: a small persistent single-instance host €10–40/month; encrypted backups/storage €1–10/month; domain €10–30/year. Support, grant review, monitoring, legal/security work and optional future email/payment fees are additional and unpriced. Hosting/network policy, actual load and retention volume could materially change these figures. No recurring service has been purchased.

Free-account ownership is not verified, so multi-account trial abuse is possible. There is no password recovery/change flow, billing, paid entitlement, team workspace, delivery infrastructure, formal service level or commercial support offering. The local prototype should be reviewed before handling real customer data.

## Three most serious risks

1. **Incomplete source and eligibility coverage.** Metadata can omit conditions, amendments, lot-specific rules and current status. The bounded feed and small grants catalogue must not be mistaken for exhaustive or legally qualified advice. Unknowns, citations and freshness help expose this limitation but do not remove it.
2. **Authentication/privacy operations are not production-qualified.** Account ownership/recovery, independent security review, complete erasure, controller/retention processes, abuse controls and tested backups are unfinished. A public launch would require these before collecting customer data.
3. **Single-instance operations and unvalidated commercial value.** SQLite needs durable storage and disciplined backup/rollback; hosted monitoring, load/failover tests and an editorial operation are absent. Billing/team concepts and proposed prices are unvalidated, so technical prototype success does not establish a viable subscription product.
